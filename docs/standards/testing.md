# Testing standards

Depth behind the testing rules in AGENTS.md.

## Measuring coverage

The bar: above 80% of lines on DirectaKit and DirectaDaemonCore.

Measure with `swift test --enable-code-coverage`, which prints nothing itself, then `xcrun llvm-cov report` against `.build/debug/DirectaKitTests.xctest/Contents/MacOS/DirectaKitTests` plus `-object` for the DirectaDaemonCoreTests and DirectaCLITests binaries at the same layout (Swift Build writes one bundle per test target), with `-instr-profile=.build/out/Products/Debug/codecov/default.profdata` and `-ignore-filename-regex='(Tests|checkouts|\.build)/'`; read the Lines column, because the toolchain emits no branch data at all and every Branches row is zero (which metric this should gate on, and a script to enforce it, are open in BACKLOG.md).

## Test targets and helpers

- Tests: DirectaKitTests is the unit-test target of record and holds the schema goldens; DirectaDaemonCoreTests drives a real Router over temp paths; DirectaCLITests covers CLI-only behavior with @testable import of the executable (argument parsing, lock notices, identity verdict). TestSupport.swift (Tests/DirectaDaemonCoreTests) is the one home for the fixture-server lookup, the shared Router test env and call helpers, and a test's raw posix_spawn (spawnBare: close-on-exec by default, since a child that inherits a concurrent test's pipe stalls that pipe's reader, and every caller waiting on it, for the child's lifetime; and a reset signal mask and dispositions by default, since a spawn from a pool or Dispatch thread otherwise hands the child a blocked SIGTERM). It is also the home for test ports: each test process leases one block from TestPorts (an flock per block, so two worktrees running at once never share one, all clear of smoke.sh's ranges), a test names its port as an offset into the block (`TestPorts.port(111)`, never a literal, which a test enforces), and fixture reaping is scoped to dead parents whose port is in the run's own block, so a concurrent run and smoke.sh are both left alone. Tests/DirectaTestSupport/Polling.swift is the one home for waiting on a condition whose timing a test does not control (firstAnswer, eventually, awaitExit: deadline-bounded, suspending between checks); a test proving something never happens asserts `!eventually(...)` over the whole window rather than sleeping. Tests/DirectaTestSupport/TemporaryTree.swift (a library target every test target depends on) is the one home for a test's scratch directories: a `.temporaryTree` suite or test gets a tree per test case, removed however the case ends, and a test source that calls Foundation's temp directory directly fails TemporaryTreeTests. Tests/DirectaTestSupport/OffPool.swift is the one home for a test's work that blocks its thread (offPool) and for running a setup process (TestProcess): a test body runs on the same cooperative pool as every parallel suite and the daemon code under test, so a process wait, semaphore, pipe read, or sleep-poll there goes through offPool, and a gate a test holds a job on opens however the test's wait ends. The same holds for TestSupport.swift's gates (Latch, SpawnGate, AdoptGate), which open synchronously so a test opens each in a `defer` declared after the `async let` or Task that waits on it: a scope unwinds in reverse order, so a defer declared earlier runs after the implicit await and a failed `#require` hangs the whole run.
